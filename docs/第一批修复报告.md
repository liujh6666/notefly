## A. 已修问题与代码位置

### P0-1 保存失败仍提示「已保存」

**根因**
1. `public/index.html:953` 的 `api()` 直接 `return await res.json()`：
   - HTTP 500 带 JSON 时原样返回，调用方看不到失败；
   - 响应不是 JSON 时抛异常被 catch，统一压成「服务未响应」；
   - 没有超时，服务卡住时界面永久等待。
2. `saveContent()` **完全不检查返回值**就 `ElMessage.success("已保存")` 并切换页面 —— 丢稿风险点。
3. 服务端 `PUT /api/contents/:id` 写盘异常时甩出 Express 默认 HTML 错误页；内存已改、磁盘未写，界面刷新后显示“已改”。

**修复**
- 新增 `public/js/api-client.js`：统一错误契约
  `{ ok:true, status, ...body }` / `{ ok:false, status, error, networkError|timedOut }`，
  覆盖 HTTP 4xx/5xx、非 JSON 响应、断网、20s 超时；**只有 2xx + 合法 JSON 才 ok:true**。
- 新增 `public/js/content-save.js`：`validate / buildPayload / save`，
  保存成功必须回传 `id` 才算数（防止被网关改成 200 空响应）。
- `index.html` `saveContent()`：失败即返回，**不跳页、不清空、不提示成功**；成功才回填 id 并提示；`ceSaving` 防连点。
- `server.js` 内容三接口：写盘失败 → 500 JSON + **内存回滚**（PUT/POST/DELETE 都做）。
- 存储层改为**原子写**：临时文件 → 备份上一版 `.bak` → rename；解析失败把损坏文件另存 `.corrupt-<时间>`，并写入 `dataWarnings`，前端启动时弹常驻错误提示（不再静默当空库）。

### P0-2 部分平台失败仍显示「完成」

**根因**（三处判定语义不一致）
- `applyRpaResult()`：`!ready.length` 即 `done` —— `[success, failed]` 没有 ready，直接判完成；
- `/api/tasks/:groupId/status` 远端分支：`some success → done`；
- `settleTask()`：要求 `every success` 才算完成。

**修复**
- 新增 `lib/task-status.js` 作为**唯一**状态归并入口：
  - 任务状态：`scheduled / creating / running / draft_ready / needs_manual / partial / done / failed / unknown`
  - 目标状态：`pending / filling / draft_saving / ready / needs_manual / submitting / accepted / reviewing / success / failed / unknown`
  - 判定优先级：**空目标 → unknown；有未知结果 → unknown；有在执行 → running；全成功 → done；全失败 → failed；成功+失败/待确认 → partial**
- `applyRpaResult` / 远端状态回写 / `settleTask` 全部改为调用 `syncTask()`；
- 状态回退时清空 `finishedAt` 并重算 `error`（不会残留旧错误）；
- 启动时对历史任务做一次静默迁移（只改派生字段）。

### 同时修掉的相关缺陷

| 问题 | 位置 | 处理 |
|---|---|---|
| 单目标重试后父任务仍 `failed` | `server.js` retry 接口 | 目标变更后立即 `settleTask()`，响应回传 `taskStatus` |
| 已成功/结果未知目标可再次提交 | submit 接口 | 已 `success` → 409；`unknown/submitting` → 409「先核验」 |
| 无待发目标却回 200 | `/submit` | 无目标 → 409，不再假装成功 |
| 调度器单个任务异常会掐断后续轮询 | `schedulerTick` | 每任务 try/catch，`setTimeout` 放 finally |
| 远端请求无超时 | `mp()` | 15s AbortController，失败统一 502 + 可读原因 |
| 定时时间可为过去/非法 | `/api/publish` | 400 明确报错 |
| 排队任务受引擎切换影响 | `/api/publish` | 创建时冻结 `engine/mode/snapshot/accountIds/frozenAt` |
| 健康检查覆盖未保存设置 | `checkEngine()` | 仅在 `force`（首次/保存成功）时刷新表单；`cfgDirty/engineDirty` 保护输入 |
