### 附带修复（测试过程中发现）

- `publishQueue` 的 TDZ 崩溃：启动恢复在模块前部执行，访问后期初始化的 `const publishQueue` 会抛 `ReferenceError` → 队列声明提前到存储层旁。
- 恢复逻辑与状态迁移的**执行顺序**：迁移会把 running 重算成 in_review，导致恢复逻辑判断失真 → 恢复移到迁移之前。
- `node --test` 子进程挂住：keep-alive 连接未关 → `closeAllConnections()` + 显式退出。
- 旧断言过时：`task-status.test.js` 里 `submitting → unknown` 与新模型冲突 → 按新语义拆成两条用例。

关键断言（真实运行输出，非推断）：

**能力闸门（batch3.test.js）**
- `unverified 微博走 publish 模式：不得调用 submit，必须停在草稿` → submit 调用次数 **0**，目标状态 `ready`，带 `capabilityLimited`
- `能力验证通过的平台：submit 被调用，但结果只能记 accepted` → submit 调用次数 1，状态 `accepted`（断言 `≠ success`），带 evidence
- `提交超时必须记 unknown` → 状态 `unknown`，错误文案含「核验」

**状态模型（batch3.test.js / task-status.test.js）**
- accepted → `in_review`、reviewing → `in_review`、submitting → `in_review`
- unknown → `unknown`（仍必须核验）
- 已发布 + 审核中 → `in_review`（不提前判完成）；全部成功 → `done`；草稿全 ready → `draft_ready`

**队列恢复（server-recovery.test.js）**
- `重启后 queued 且从未执行的任务会重新入队并执行` → 执行次数 1，状态回到 `draft_ready`，history 记录 `requeued_after_restart`
- `执行到一半中断的任务：转人工核验，绝不自动重发` → 执行次数仍为 1（**没有重发**），submitting → `unknown`，父任务 `unknown`

**核验状态机（server-recovery.test.js）**
- 已 success 目标 confirm_failed → **409**，状态不变
- 已 success 目标 confirm_success → 409（幂等）
- unknown 目标 confirm_failed → 200，标 `verifiedBy: manual`，之后可重试

**词库（server-recovery.test.js）**
- 词库可用 → `status: checked`，命中风险词
- 词库文件缺失 → 自动初始化默认词库 → 仍 `checked`
- 词库路径被占成目录 → `status: unavailable` + note 含「未检测」

**界面（ui-smoke.js）**
- 平台清单按 ID 加载（含 juejin）
- 打开平台菜单区分「创作后台 / 平台首页」
- 打开平台不再提示「未收录该平台首页地址」
- 未来定时任务已排入到点唤醒 → 到点唤醒定时器已触发 → 到点后自动同步一次
- 原 27 项断言（保存失败不谎报 / 部分成功 / 断网 / 400 / 202 排队）全部保持通过

**真实数据回归**
- 7 条历史任务状态完好（3 条 draft_ready / 4 条 failed），无中断任务，恢复逻辑未误触发
- 界面能力表加载正确：掘金 `draft=verified, autoSubmit=unverified, verify=unverified`
- 顶栏文案已改为「引擎：NoteFly RPA」
- 改动前备份 `data/store.json.pre-batch3-*`

## 三、本批**没有**做的事（必须说清）

1. **没有验证任何平台的真实发布**。全部用 Playwright 替身 + 预置数据验证**决策分支**。
   「能力表里哪些平台该标 verified」必须由真实账号逐个验，不能靠代码推断。
2. **自动提交能力目前一个平台都没有 verified**。因为「点完按钮等几秒」无法构成发布证据。
   要把某平台升到 `autoSubmit: verified`，必须补齐证据链：
   - 草稿保存证据（草稿箱存在该稿 + 草稿 ID）
   - 提交受理证据（作品 ID / 管理页出现记录）
   - 审核状态（reviewing → published）
   - 最终发布证据（公开 URL / 作品 ID）
   本批已把 `accepted` / `reviewing` / `unknown` 的状态位和归并准备好，等着接证据。
3. **A/B/C 三项功能交付未开始**：多平台独立窗口登录与账号主页入口、一键排版（风格/预览/应用/撤销/保存）、导航与编辑到分发的流程整理。
   本批只把「打开平台按 ID 取地址」修好，尚未做到「两个平台同时开独立窗口、互不覆盖」。
4. **账号主页入口未做**：当前只到平台级地址（创作后台/首页）。账号主页需要账号级 URL，
   不能复用一个未区分账号的泛平台入口。
