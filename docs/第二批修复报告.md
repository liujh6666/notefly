# 第二批修复报告：交互错误修复（对应《NoteFly 1620 版复审与界面改版任务书》第二节 + 第三节）

日期：2026-11-02 17:30　·　基线：16:20 版源码包复审意见

## 交付范围说明

本轮只做任务书明确要求的"先修前后端交互"（第二节 1–7）与第三节能从代码确认的矛盾。
界面大改版（第五节六项导航）、多平台并行登录窗口（第八节）、一键排版（第九节）是独立批次，本轮未动，避免一次改太多无法归因。

## 一、逐项修复对照

### 第二节 1：doPublish() 只处理 status>=500 → 已修

- `public/index.html` `doPublish()`：**任何 `!r.ok` 都进错误分支**。断网（status:0）、超时、HTTP 400/401/413/500 一律 `apiError("发布失败", r)`，绝不再落到"已加入定时队列/任务已创建"的成功提示。
- 定时创建成功的提示改为**必须以服务端返回的 `task.scheduledAt` 为准**：`"已加入定时队列：" + fmt(task.scheduledAt) + " 自动执行"`。服务端没确认任务就不可能显示这句话。
- HTTP 400 校验失败：显示服务端原文（如"定时时间必须晚于当前时间"），不跳页。

### 第二节 2：失败响应里的 task 被请求层包住 → 已修

- 新增统一取值函数 `taskOf(r)`：2xx 时业务字段展开在顶层，非 2xx 时从 `r.body.task` 读。**所有按钮不再各自猜响应层级**。
- 服务端配合：所有返回任务的接口统一用 `publicTask()`（去掉 snapshot 大字段）；单目标提交、批量提交现在都回传完整 `task`。
- `!ok` 但带了已持久化任务时：提示"服务端返回异常，但任务已创建（未重复创建）"，照常展示任务与状态并跳发布记录——用户不会因为一次 5xx 就重复发稿。

### 第二节 3：checkInterval 没加载 → 已修

- `checkEngine(force)` 现在回填 `cfg.checkInterval`（服务端 `/api/config` 本来就返回它）。
- `saveInterval` 增加 `ok` 判断，失败时提示而不是假装成功；成功后同步本地值。
- 运行态（engineOk/dataWarnings）与设置表单继续分离：后台健康检查不覆盖未保存的表单。

### 第二节 4：单目标提交后弹窗头部状态不同步 → 已修

- 服务端单目标提交/重试/批量提交接口都回传完整 `task`（含重算后的总状态）。
- 前端 `applyTaskFromResponse` 改用 `taskOf(r)` + 按 `task.id` 匹配，同时更新列表项与 `curTask`。
- 回归用例：`单目标提交回传完整任务，父任务从 draft_ready 重算为 partial`（server.test.js）。

### 第二节 5：任务状态误用目标字典 → 已修

- 任务状态与目标状态是两套字典（`statusName` / `tName`），提示一律用 `statusName[st]`，不再出现 `tName[r.taskStatus]` 把 `partial` 翻成英文的情况。
- 新增 `queued`（排队执行）状态文案，前后端一致。

### 第二节 6：20 秒超时 vs 同步执行多平台 → 已修（架构改动）

- **服务端**：`/api/publish`（RPA 立即执行）改为**持久化任务后立即返回 202 + `taskStatus: "queued"`**，实际填充交给进程内执行队列（同一时刻只跑一个任务，避免多任务争抢浏览器页面）。定时任务到点也走同一条队列。
- **前端**：新增任务轮询——有进行中任务时每 2.5 秒拉一次 `/api/tasks` 并同步详情弹窗；全部到终态自动停止；页面从后台切回前台立即补一次同步。取消等待/关弹窗不影响后台执行。
- 回归用例：`发布接口快速返回 queued 任务（不等待多平台执行完）`——断言 1.5 秒内返回。

### 第二节 7：unknown 只有提示没有入口 → 已修

- 服务端新增 `POST /api/tasks/:groupId/targets/:accountId/verify`：
  - `action=check`：自动核验（执行页面是否还在）+ 明确的下一步提示；
  - `action=confirm_success`：人工确认已发布，**明确标记 `verifiedBy: "manual"`**，绝不伪造成平台自动核验；
  - `action=confirm_failed`：人工登记失败，之后可正常重试。
- 重试接口现在**同样拒绝 unknown**（与前端一致），提示"不能直接重填，请先核验"。
- 任务详情弹窗 unknown 行提供四个动作：**打开平台 / 核验 / 确认已发布 / 登记失败**；人工确认过的目标显示"人工确认"标签。

### 顺带修掉的真实崩溃（测试过程中发现）

- `store.json` 缺 `accountMeta` 顶层键时，`/api/accounts` 直接把服务打崩。启动时现在统一补齐 `contents/tasks/accountMeta` 缺失键。
- 历史遗留 `publishing` 状态且无目标记录的任务，启动迁移为 `unknown`（"历史任务：执行结果未记录，请人工核验"），不再永远"进行中"。
